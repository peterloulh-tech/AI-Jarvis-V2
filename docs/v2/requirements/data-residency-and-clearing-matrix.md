# AI Jarvis V2 数据分类、驻留与清除矩阵

> 任务：AIJARVISV2-6
> 适用基线：NFR-05.01、NFR-06.01、NFR-08.01；FR-18.01～18.04；AC-D01～D06。

“上限”可以是冻结槽位数、每次运行唯一实例，或实现时必须暴露并记录的 `configured_limit`/保留期限。凡写为“配置上限”的项目都必须在测试记录中填写实际值和触顶动作；这不是允许无限保留，也不在本任务虚构未经实测的固定数值。

## 2. 生命周期状态转换

| 触发 | 必须清除/失效 | 允许保留 | 禁止结果 |
|---|---|---|---|
| 覆盖/任务完成 | 已消费的原始帧、音频块、任务中间量 | 新的当前槽/窗口，必要任务元数据 | 原始音画进入历史队列或日志 |
| 暂停 | 新采集/分析入口、队列、短时上下文、摘要、在途结果有效性 | 当前进程有界轻量历史、滚动元数据日志、配置锁定 | 暂停后继续新增原始数据或补发旧结果 |
| 停止 | 原始音画、模型中间量、短时上下文、运行队列和模型资源 | 当前进程内有界轻量历史/高光时间线、滚动日志、稳定配置 | 把停止误当作长期保存或自动导出 |
| 再次开始 | 上一运行的轻量历史、高光时间线、运行快照和旧代次引用 | 稳定用户配置、程序/模型包及受控清单 | 旧运行内容进入新 run_id/run_generation |
| 正常关闭 | 进程内数据、滚动诊断日志、运行期临时文件、锁标记 | 稳定配置、程序/模型包、用户已导出的诊断包 | 关闭后后台保留历史、日志或上传缓存 |
| 异常退出后重启 | 上次残留进程和最小临时状态；锁标记在处理后清除 | 仅处理前的最小锁标记；不含用户内容 | 借异常恢复保留原始音画、旧会话或长期日志 |
| 手动诊断导出 | 不改变源数据生命周期；导出完成后关闭临时打包区 | 用户选择目标中的单个诊断包 | 自动上传、默认弹幕正文、任何原始音画 |

任务 4 仍定义暂停、停止、异常退出和清理动作。本表只定义这些动作在任务 6 数据类上的隐私结果，不创建新的恢复状态或故障机制。

## 3. 上限与清除证据规则

1. 所有写为“配置上限”的数据类必须记录 `data_class_id`、`limit_kind`、`configured_limit`、`observed_peak`、`limit_action` 和 `clear_trigger`。
2. 达到上限时只允许覆盖、淘汰、拒绝或停止等已登记动作；不得退化为无限增长。
3. 验证必须依次执行开始、运行、暂停、恢复、停止、再次开始和关闭，并在各边界记录条目数、字节数、文件数或端点数。
4. 原始音画的持久化/上传计数是冻结的 0；其他尚无冻结数值的容量不得在本任务写成最终产品承诺。
5. 若实现无法提供实际上限或清除证据，结果为 `DATA_INCOMPLETE`；若发现未登记持久化/上传，结果为 `FAIL_FROZEN`。

| Case ID | 操作 | 必查数据类 | 可观察通过结果 |
|---|---|---|---|
| LIFE-TEST-001 | 开始并产生轻量历史/高光记录，停止后查看，再次开始 | DATA-006～010 | 停止后仅当前进程允许查看有界记录；再次开始后上一 run_id 的历史、高光、上下文和运行快照有效数为 0 |
