## 1. 执行与记录约定

每次执行必须记录环境、程序/模型/运行时版本、输入或故障注入、开始/结束时间、原始证据路径和结论。结论只能为 `通过`、`失败`、`阻塞`、`不适用`；P0 失败阻止阶段通过，P1 必须形成数据记录，但未校准数值不得写成承诺。

前置条件缩写：

- `WIN`：Windows 11 64 位、NVIDIA 独显、简体中文、完整离线包；显示场景按任务 14 的真机矩阵取值。
- `O`：O 模型与持续音画回放可用，TTS 关闭，可注入触发、结构损坏、超时和进程退出。
- `V`：V 模型与固定录像可用，可配置 1～3 路/1～3 图并注入乱序、过期、旧代次和服务故障。
- `LOAD`：可控制发送池/队列/高光并发、时效与资源采样；可重复运行固定输入。
- `FAULT`：可使画面、音频、Overlay、模型或子进程显式失效，并保留 UI、日志、进程树和资源证据。
- `PKG`：干净系统、已安装版本、程序增量包、模型替换包和卸载入口均可用。

证据至少来自一种可复核通道：`UI`（截图/录屏/控件状态）、`LOG`（事件/任务/批次/代次/错误）、`RES`（进程、显存、内存、句柄、队列）、`FS`（安装、配置、日志、诊断包、原始音画扫描）、`NET`（断网结果或网络抓取）。

所有条目隐含追踪 `NFR-01`、`NFR-09` 和最终门任务 `AIJARVISV2-89`；三个 P1 条目另隐含 `NFR-10`。表中“任务”只列最直接的规划/执行责任入口，数字 `N` 表示 `AIJARVISV2-N`，不替代共享追踪矩阵。
