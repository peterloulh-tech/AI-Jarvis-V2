## 3. 待实测校准指标

以下指标已有统一计算口径，但没有最终通过门槛：

- MET-T01～T12：启动、加载、首条弹幕、V 推理、O 输出、端到端、排队、内容时效、停止和恢复耗时。
- MET-R01、R02、R04～R07：显存、内存、句柄、GPU 与持续忙碌比例的数值门槛。
- MET-R03：模型显存必须释放已冻结；区分驱动基线与模型进程专属分配的归因方法、采样等待窗口待校准。
- MET-R08、R09：所有结构必须有上限已冻结，具体安全容量、日志容量与增长门槛待后续任务确定并验证。
- MET-S04：故障时 UI 必须能响应已冻结，响应耗时门槛待实测。
- MET-S08、S09：重启、过期、淘汰和失败必须记录，目标率或保护阈值中未冻结部分待实测。
- NFR-05.02 的 8/12/16GB 是冻结的初步产品边界，但不同模型和场景的实际吞吐、延迟、峰值和综合游戏能力仍需实测。

MET-T13 的 O 12/16/20 秒不在待重新确定列表中；后续只能验证其合理性，不能在本链路擅自改值。

## 6. P0/P1 统一解释

- **P0**：候选验收中的发布阻断标签。它通常验证冻结硬要求；P0 标签本身仍随验收 V0.1 保持候选状态。
- **P1**：必须完成测试和记录、但量化门槛尚需模型选型或真机校准的项目。不得把 P1 数据写成当前对外承诺。
- 冻结 NFR 的“硬要求/工程目标”分类优先于候选验收的 P0/P1 表述；两者不一致时，以冻结 NFR 为准并登记评审。

未发现自相矛盾或完全无法测量的冻结要求，但以下九类定性表述没有冻结数值门槛。这里仅固定观测方法，不替它们擅自填值：

| ID | 冻结表述 | 可观测化处理 | 剩余状态 |

| AMB-01 | “常见单显示器和多显示器” | 后续兼容矩阵列出实际显示拓扑并逐项记录 | 具体矩阵待 AIJARVISV2-5/14 确定 |

| AMB-03 | UI 不得“长时间白屏或未响应” | 记录 OS 未响应状态及 MET-S04 响应耗时 | 最终耗时门槛待实测 |
| AMB-04 | 暂停/停止后“立即”停止接收新任务 | 使用 MP-03→MP-04 记录耗时并核验之后新增任务数为 0 | 耗时门槛待实测 |
