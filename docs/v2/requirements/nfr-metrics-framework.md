## 1. 使用规则

1. 所有时间差使用同一台机器上的单调时钟计算；UTC 墙上时间只用于日志关联，不参与耗时计算。
2. 所有持续时间内部记录为整数微秒，报告统一换算为毫秒；持续运行时间报告为小时。
3. 同一统计集合必须保持模式、模型及版本、量化、运行时、硬件、驱动、画面输入、并发、档位、配置快照一致；不同条件不得混算。
4. P50、P95 按升序样本的 nearest-rank 计算：`Q(p)=x[ceil(p×N)]`。报告必须同时给出样本数 N、最小值、最大值、P50、P95；小样本不得隐藏原始分布。
5. 失败、取消、过期、降级和成功样本分别计数。延迟分位数默认只统计完整有效样本，失败率必须单独报告，不能用丢弃失败样本来美化延迟。
6. “待实测校准”表示必须记录数据，但当前没有最终通过门槛；不得把采样结果自动升级为冻结承诺。
7. 冻结硬要求仍以 `NFR-*` 条目为准。候选 `AC-*` 只提供测试入口，不改变非功能需求状态。
8. O 模式生成硬超时继续保持：内置档 12 秒；自定义档按输出预算使用 12/16/20 秒。该数值不属于待重新确定项。

## 2. 统一度量词汇（40）

| ID | 词汇 | 统一定义 |
|---|---|---|
| TERM-001 | 观察时间 `observed_at` | 系统认定事件所对应主要音画或画面的单调时钟时间；用于统一内容时效起点。 |
| TERM-002 | 采集时间 `captured_at` | 一帧画面或音频块进入采集子系统并获得本机单调时间戳的时点。 |
| TERM-003 | 提交时间 `submitted_at` | 编排器把一次可执行模型任务交给模型服务的时点；进入模型侧等待也算已提交。 |
| TERM-004 | 推理开始 `inference_started_at` | 模型服务实际开始处理该任务或开始本轮文字生成的时点。 |
| TERM-005 | 首个输出 `first_output_at` | 模型服务产生第一个可观测输出片段的时点；不要求该片段已构成有效弹幕。 |
| TERM-006 | 完整结果 `result_completed_at` | 模型服务结束本轮输出并交付完整结构化结果或明确失败的时点。 |
| TERM-007 | 校验完成 `validated_at` | 主程序完成结构解析、字段补齐及丢弃规则后，确定有效结果集合的时点。 |
| TERM-008 | 入池时间 `enqueued_at` | 有效批次进入普通发送池、普通等待队列或高光发送流程的时点。 |
| TERM-009 | 发送开始 `send_started_at` | 批次发送器接受批次并开始执行发送窗口的时点。 |
| TERM-010 | 首条显示 `first_displayed_at` | 本批第一条有效弹幕实际提交给 Overlay 并确认可显示的时点。 |
| TERM-011 | 末条显示 `last_displayed_at` | 本批最后一条实际显示弹幕完成提交的时点。 |
| TERM-012 | 控制请求时间 `control_requested_at` | 用户或系统发出开始、暂停、恢复、停止或退出请求的时点。 |
| TERM-013 | 停止接收新任务 `new_work_blocked_at` | 控制器已阻止新的分析任务和弹幕发送任务进入系统的时点。 |
| TERM-014 | 故障检测时间 `fault_detected_at` | 已有显式错误信号首次被主程序确认的时点。 |
| TERM-015 | 恢复就绪时间 `recovery_ready_at` | 恢复动作完成，系统重新达到冻结规则允许的可操作或可运行状态的时点。 |
| TERM-016 | 清理完成时间 `cleanup_completed_at` | 模型、采集、Overlay 和相关子进程结束，显存及运行期临时资源完成清理的时点。 |
| TERM-017 | 有效样本 | 满足指定采样条件、时间点齐全且结果分类明确的一次观测；失败样本保留但不混入成功延迟分位数。 |
| TERM-018 | 测量窗口 | 具有明确开始、结束和固定环境配置的一段测试区间。配置变化后必须开启新窗口。 |
| TERM-019 | P50 | 按统一 nearest-rank 规则计算的第 50 百分位；表示同一采样条件下的中位水平。 |
| TERM-020 | P95 | 按统一 nearest-rank 规则计算的第 95 百分位；用于观察高尾延迟，不等同最大值。 |
| TERM-021 | 硬超时 | 从指定开始点起，到固定时限仍未得到规定完整结果时必须触发的失败边界；中途输出不延长时限。 |
| TERM-022 | 启动时间 | 从主进程创建到配置页面可交互的持续时间；与模型加载时间分开。 |
| TERM-023 | 首次有效弹幕延迟 | 从开始请求被接受到当前运行会话第一条通过校验且实际显示的文字弹幕之间的时间。 |
| TERM-024 | 端到端时延 | 从 `observed_at` 到 `first_displayed_at` 的时间，包含采集后处理、模型、校验、排队和发送。 |
| TERM-025 | 队列驻留时间 | 从批次进入等待队列到被发送池领取或被淘汰的时间；不等同内容总年龄。 |
| TERM-026 | 内容年龄与过期 | 在判定时点减去 `observed_at`；超过适用时效边界即过期。时效包含生成与等待耗时。 |
| TERM-027 | 恢复时间 | 从 `fault_detected_at` 到 `recovery_ready_at` 的时间；不同故障类型不得混算。 |
| TERM-028 | 显存占用 | 指定 GPU 上 AI Jarvis 当前相关进程使用的显存总量，报告 MiB 和采样来源。 |
| TERM-029 | 显存峰值 | 同一测量窗口内显存占用样本的最大值，不用单点峰值替代完整趋势。 |
| TERM-030 | 资源增长趋势 | 固定窗口内显存、内存或句柄随时间的变化序列及斜率；用于识别持续单向、无上限增长。 |
| TERM-031 | 持续忙碌比例 | 指定窗口内模型处于实际推理或生成状态的累计时长除以窗口有效运行时长。 |
| TERM-032 | 有界结构 | 具有明确容量或保留期限，达到上限时有确定覆盖、淘汰或拒绝规则的队列、缓冲、历史或日志。 |
| TERM-033 | 故障隔离 | 模型、采集或 Overlay 单组件故障时，主程序仍可响应并能执行冻结要求中的停止或退出。 |
| TERM-034 | 降级 | 可选输入失效后，系统按冻结规则使用剩余输入继续运行；不是自动降低模型、质量或用户配置。 |
| TERM-035 | 正式稳定性验收 | 在规定环境与固定输入下连续运行 4 小时的正式验收窗口。 |
| TERM-036 | 内部压力测试 | 使用固定输入或录像回放连续运行 8 小时的内部工程测试；不作为对外承诺。 |
| TERM-037 | 诊断记录 | 能关联版本、硬件、配置快照、错误、耗时、重启和有界结构状态的结构化元数据；默认不含原始音画。 |
| TERM-038 | 数据保留边界 | 数据允许存在的位置、容量或期限以及清除时点；未定义边界的数据不得无限保留。 |
| TERM-039 | 核心离线运行 | 完整安装后，在断网且不登录账号、不在线下载模型的条件下完成核心运行闭环。 |
| TERM-040 | 孤儿进程 | 主程序停止、退出或异常退出后仍存活且属于该运行会话的模型、采集或 Overlay 子进程。 |

## 4. 状态使用规则

- **正式冻结（数值/规则）**：必须原样执行，例如 4 小时、8 小时工程目标、Windows 11 64 位、显示矩阵以及 O 12/16/20 秒。
- **正式冻结（结果要求）**：通过结果不可降级为建议，例如不得崩溃、必须可停止、不得残留孤儿进程、不得自动上传原始音画。
- **定义已固定；门槛待实测**：测量起止点和算法在本任务统一，但最终允许值仍是 `待实测校准`。
- **冻结要求＋待校准数值**：例如“所有结构必须有上限”是硬要求，而具体安全上限由后续任务与实测确定。

任何后续任务不得给同一 `MET-*` 创建第二套起止点或分位数算法；确需变更时必须回到本度量框架评审，并证明没有改变冻结需求。
