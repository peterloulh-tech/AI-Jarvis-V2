## 2. 安装、更新与卸载原则

1. **普通用户自包含安装。** 用户无需预装 Python、Node.js 或开发环境即可安装并打开配置页；发布包必须携带核心运行所需且允许再分发的程序依赖和运行时。
2. **程序与模型解耦。** 程序包、模型包和用户配置是三个独立生命周期；程序小版本更新不要求重新下载全部模型，模型替换不要求重新安装整个程序。
3. **完整离线闭环。** 完整离线包预先包含声明的程序、运行时和所选模型；包到达目标机后，从安装开始到 Local O / Local V 核心闭环、停止和诊断导出均不得依赖账号、登录或在线下载模型。
4. **联网必须由用户主动。** 第一版不自动检查、静默下载、后台下载、强制更新或连接后台版本服务；允许的获取或更新联网必须由用户当次明确操作触发。
5. **先验证后激活。** 安装或替换前核对清单、版本兼容和完整性；新内容只有在验证完成后才可成为活动版本。
6. **失败不破坏已知可运行版本。** 更新失败、取消、摘要不匹配或兼容检查失败时，变更前的程序、模型和配置组合仍须可启动并完成原有核心闭环。
7. **卸载选择显式且默认保留配置。** 卸载界面必须明确询问是否删除个人配置，默认不删除；无论选择哪种配置处理方式，卸载完成后模型、采集和 Overlay 相关进程均为 0。
8. **版本化可诊断。** 安装、更新、回退、卸载、运行日志和手动诊断包必须能关联程序包、模型包、运行时、清单和日志结构版本。

## 4. 用户主动联网边界

| 行为 | 第一版是否允许 | 必要触发 | 空闲/后台允许 | 取消或失败后的要求 |
|---|---:|---|---:|---|
| 本地完整离线包安装 | 是 | 用户启动本地安装包 | 否 | 不启动在线补齐；记录本地失败 |
| 本地程序包更新 | 是 | 用户选择并确认本地包 | 否 | 保留已知可运行程序版本 |
| 本地模型包替换 | 是 | 用户选择并确认本地包 | 否 | 保留原活动模型 |
| 用户主动从明确来源获取包 | 可规划，但不由本任务实现 | 当次用户明确操作 | 否 | 停止下载；不得后台继续或自动激活 |
| 自动版本检查/后台版本服务 | 否 | 无合法触发 | 否 | 发现即 `FAIL_FROZEN` |
| 静默、强制或后台更新 | 否 | 无合法触发 | 否 | 发现即 `FAIL_FROZEN` |

本节允许的安装/更新联网不等于允许上传本地内容。Online 模型运行期的必需音画上传及其停止边界，以 `threat-boundaries-and-network-behavior.md` 与 `privacy-security-nfr.md` 为准。
