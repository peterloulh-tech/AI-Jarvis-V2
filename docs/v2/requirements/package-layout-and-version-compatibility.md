# AI Jarvis V2 包布局与版本兼容规则

> 任务：AIJARVISV2-7
> 追踪：FR-20；NFR-07.01/08.01；TERM-037/039；MET-C04/C06/C07；OOS-078～080。

本文件定义发布资产的逻辑边界、清单契约、兼容判定和失败保护。逻辑边界不规定 Windows 绝对路径、安装器产品、压缩格式、签名方案或更新传输协议。

## 1. 逻辑包与状态边界

| ID | 对象 | 必须包含/记录 | 不得耦合的内容 | 生命周期 |
|---|---|---|---|---|
| PKG-001 | 程序包 | 主程序、受控运行时、允许再分发依赖、资源、schema、程序清单 | 模型权重；个人配置；运行日志；诊断导出 | 随程序小版本安装/更新 |
| PKG-002 | 模型包 | 模型权重及其必要配套文件、模型身份、量化、兼容声明、来源/许可引用、模型清单 | 主程序二进制；个人配置；运行日志 | 独立安装、验证、替换或保留 |
| PKG-003 | 用户配置 | 用户稳定配置、配置 schema 版本和必要迁移/校验结果 | 程序二进制；模型权重；失效窗口句柄、进程 ID、旧运行会话 | 程序更新时尽量保留；卸载默认保留 |
| PKG-004 | 运行诊断记录 | 有界日志、版本化事件和最小异常锁标记 | 原始音画、无限追加内容、自动上传缓存 | 遵守任务 6 的驻留/清除边界 |
| PKG-005 | 手动诊断包 | 用户主动导出的版本化最小化副本及内容清单 | 程序/模型文件、原始音画、自动上传配置 | 完成/取消/失败按任务 6 清理 |
| PKG-006 | 更新暂存 | 本次待验证包、清单和阶段结果 | 被业务运行路径直接当作活动版本 | 完成、取消或失败后清除 |

`PKG-001` 与 `PKG-002` 必须能分别识别和替换；`PKG-003` 必须不因程序卸载默认消失。实际目录由后续架构/安装实现任务确定，但必须证明这些边界没有混入同一不可分割更新单元。

## 2. 发布清单最小契约

| 字段 | 程序包 | 模型包 | 规则 |
|---|---:|---:|---|
| `manifest_schema_version` | 必填 | 必填 | 解析失败不得激活 |
| `package_id` / `package_type` | 必填 | 必填 | 类型必须为受支持的程序或模型类别 |
| `package_version` | 必填 | 必填 | 原样写入安装、更新、日志和诊断记录 |
| `build_commit` | 必填 | 可选 | 程序包必须可追溯到构建提交 |
| `runtime_version` | 必填 | 兼容声明必填 | 用于模型与程序运行时兼容判定 |
| `model_id` / `model_version` / `quantization` | 不适用 | 必填 | 不得只用文件名代替稳定身份 |
| `compatible_app_versions` | 不适用 | 必填 | 表达模型允许的程序版本集合，不在本任务指定语法 |
| `compatible_runtime_versions` | 必填或内含 | 必填 | 激活前双方声明必须相交 |
| `config_schema_versions` | 必填 | 不适用 | 更新后配置校验使用 |
| `source_ref` / `license_ref` | 必填 | 必填 | 只记录可审计引用，不在本任务判定许可完成 |
| `size_bytes` | 必填 | 必填 | 与实际文件集合核对 |
| `digest_algorithm` / `expected_digest` | 必填 | 必填 | 实际摘要不匹配时阻断使用 |
| `entries[]` | 必填 | 必填 | 至少含相对条目、大小和摘要；不得含用户绝对路径 |

任务 6 的完整性边界仍为上位规则。本文不声明摘要算法、签名方案或供应链审计已经完成。

## 3. 活动版本身份元组

每次启动、更新、回退、卸载和诊断导出使用同一逻辑身份：

```text
app_package_id + app_package_version + build_commit
runtime_version + runtime_manifest_digest
model_id + model_version + quantization + model_manifest_digest
config_schema_version + log_schema_version
```

同一次操作的暂存、激活、运行日志和诊断包必须能比较该元组。正文不要求用单一字符串拼接，也不规定数据库或文件格式。

## 4. 兼容判定矩阵

| Case ID | 变更 | 激活前判定 | 允许结果 | 失败保护 |
|---|---|---|---|---|
| COMPAT-001 | 全新完整离线安装 | 程序、运行时、所选模型清单完整；摘要匹配；版本声明相容 | 激活整套已验证组合 | 不生成部分可运行状态；保留失败证据 |
| COMPAT-002 | 程序小版本更新 | 新程序可读取现有配置 schema；现有模型声明兼容新程序/运行时 | 仅替换程序侧，模型不重下，兼容配置保留 | 不兼容或校验失败时旧程序/模型/配置组合仍可运行 |
| COMPAT-003 | 模型包替换 | 新模型摘要匹配，且兼容当前程序和运行时 | 只激活新模型，程序身份不变 | 旧活动模型不被破坏；新模型不加载 |
| COMPAT-004 | 配置校验/转换 | 新程序声明支持现有 schema，且转换结果可验证 | 保存可用新配置并记录前后 schema | 不覆盖唯一已知可用配置；回到变更前组合 |
| COMPAT-005 | 清单缺失、损坏或未知 schema | 无法完成受控解析和比较 | 不激活 | 活动组合不变；记录稳定错误码 |
| COMPAT-006 | 用户取消 | 尚未完成激活确认 | 不激活暂存内容 | 清理暂存；活动组合不变 |

兼容结论只能是 `compatible`、`incompatible`、`unknown`。`unknown` 与 `incompatible` 均不得进入活动版本；不得用“尝试运行看看”替代激活前检查。

## 5. 手动更新阶段与回退不变量

| 阶段 | 必须完成 | 可观察记录 | 不变量 |
|---|---|---|---|
| `precheck` | 确认停止状态、用户触发、包类型、空间/权限前置和当前身份 | operation_id、from identity、precheck result | 活动版本未变 |
| `stage` | 将候选包放入非活动暂存边界 | staged package identity、bytes、source kind | 业务运行不读取暂存包 |
| `verify` | 清单、大小、摘要、兼容和配置保留检查 | manifest/digest/compat/config results | 任一失败仍未激活 |
| `activate` | 以可恢复的边界切换活动身份 | to identity、activation result | 不能留下程序/模型跨版本半组合 |
| `postcheck` | 启动/加载和版本身份核对，按适用路径完成核心冒烟 | observed identity、outcome、evidence | 成功才提交为已知可运行版本 |
| `rollback` | 恢复变更前活动身份并复核 | rollback reason/result、restored identity | 更新失败不破坏原可运行版本 |
| `cleanup` | 清除暂存和半成品，保留有界元数据 | temp residue、cleanup result | 不自动重试或转后台下载 |

上表规定结果与证据，不指定文件替换、链接、目录交换或事务数据库等实现技术。

## 6. 保留与删除规则

| 路径 | 程序包 | 模型包 | 用户配置 | 运行/诊断记录 |
|---|---|---|---|---|
| 程序小版本更新成功 | 替换为新版本 | 保留且不重下全部模型 | 兼容时保留并校验 | 按任务 6 边界保留操作元数据 |
| 程序更新失败/取消 | 保留或恢复原版本 | 不变 | 不覆盖原可用配置 | 记录失败阶段和回退结果 |
| 模型替换成功 | 不变 | 仅选定模型变更 | 不变 | 记录前后模型身份 |
| 模型替换失败/取消 | 不变 | 原活动模型不变 | 不变 | 记录失败阶段 |
| 卸载默认路径 | 删除程序安装内容 | 由后续产品/安装说明明确，不在本任务擅自决定 | **保留** | 按任务 6 的清除/导出规则执行 |
| 卸载明确选择删除个人配置 | 删除程序安装内容 | 同上 | 删除用户配置并给出结果 | 不因此放宽日志/诊断隐私边界 |

模型文件在卸载时的保留/删除策略若冻结资料未明确，必须在后续安装设计中记录并评审；不得把“删除个人配置”选项暗中扩展为删除模型或其他用户资产。

## 7. 受保护边界

- 不修改 `nfr-metrics-framework.md`、`nfr-measurement-points.md` 或任务 3～6 文件。
- 不重写任务 4 的停止/清理/恢复状态机；这里只验证更新和卸载前后结果。
- 不放宽任务 6 的字段允许列表、联网行为、数据清除或诊断包排除项。
- 不把兼容范围语法、安装目录、更新协议或回退实现冻结为业务架构。
