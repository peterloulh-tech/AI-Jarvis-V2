## 1. 状态和判定规则

| 状态 | 含义 | 本任务的判定方式 |
|---|---|---|
| 冻结通过 | 已有冻结值或结果边界，实测只能验证是否满足 | 逐次判定，不用平均值掩盖失败 |
| 边界符合 | 硬件或结构表述已冻结，但真实性能能力仍待实测 | 先核对环境/结构，再记录性能数据 |
| 待实测校准 | 指标和采集口径已固定，最终数值门槛未冻结 | 必须产出原始记录和汇总，不得判成最终性能通过 |
| P1 数据完成 | 候选验收要求数据完备，尚不构成对外承诺 | 核对分组、样本、分位数和证据完整性 |
| 待评审 | 实测暴露冲突或需形成新门槛 | 记录证据，交后续评审；不得在本文件改值 |

统一统计规则如下：

1. 同一 `sample_group` 内固定模式、模型/量化/运行时、硬件、驱动、输入、并发、档位和配置快照；条件变化必须新建分组。
2. 耗时由同机单调时钟计算，内部以整数微秒记录、报告换算为毫秒；P50/P95 使用 `Q(p)=x[ceil(p×N)]` 的 nearest-rank。
3. 每组至少报告 N、min、max、P50、P95；吞吐报告有效任务数/有效窗口时长；失败、超时、取消、过期、降级分别计数并给出分母。
4. 超时样本不得以超时上限充当完成时延。预热样本是否纳入必须在场景中声明，原始记录全部保留。
5. 当前没有最终数值门槛的项目只能标记为“数据完成／待实测校准”或“待评审”，不能写成“性能通过”。

## 3. 指标采集方法

### 3.1 测试前锁定

- 记录 Windows、GPU 与显存、CPU、RAM、驱动、电源策略、显示器/分辨率/缩放、应用提交、模型/量化/运行时、配置快照哈希和回放资产哈希。
- 将采样间隔、预热规则、进程归属规则和有效窗口写入场景记录；本任务不擅自规定它们的最终值。
- 确认 O/V 仅加载所选模型；V 记录共享权重实例，O 记录单会话和单生成流。
- 原始音画只作为受控测试输入，不写入性能日志；统计记录只保留去标识化元数据和证据引用。

### 3.2 事件与资源关联

- 延迟链路以 `run_id`、`run_generation`、`task_id`、`event_id`、`batch_id` 连接 MP-07～17。
- 资源采样以同一 `window_id` 和 `hardware_profile_id` 关联 MP-22；进程集合必须包含主程序、模型、采集和 Overlay 的相关进程。
- 停止前后资源用 MP-03 与 MP-23 分界，保留停止前值、停止后值、驱动基线和剩余 PID，避免把驱动保留误判为模型未释放。
- 聚合报告必须可追溯到 `performance-sample-record.csv` 和 `resource-trend-record.csv` 的单条记录。

### 3.3 结果标记

| 结果标记 | 使用条件 |
|---|---|
| `PASS_FROZEN` | 冻结结果或冻结数值被逐次验证满足，例如 O 超时规则、共享权重、4h 崩溃数 0 |
| `FAIL_FROZEN` | 任一冻结结果不满足；不得以平均值覆盖 |
| `DATA_COMPLETE_PENDING_CALIBRATION` | 数据、分组和统计齐全，但最终门槛尚未冻结 |
| `DATA_INCOMPLETE` | 必要环境、测量点、样本、失败分母或证据缺失 |
| `REVIEW_REQUIRED` | 需要确定门槛、出现基线冲突或证据无法支持冻结表述 |

## 4. 对外承诺边界

可以按原文对外表述：Windows 11 64 位、NVIDIA 独显；V 最低目标 8GB、推荐 12GB 及以上；O 为 16GB 主要供模型使用的模型独占基线；V 1～3 路共享一份权重；O 单模型、单会话、单生成流；O 内置 12 秒及自定义 12/16/20 秒硬超时；4 小时正式稳定性窗口与主程序崩溃数 0。

在模型、量化、运行时与 Windows 真机证据评审完成前，不得对外承诺启动/加载时间、首次有效弹幕、模型首输出、完整结果、P50/P95、吞吐、端到端总时效、V 硬超时、资源峰值、增长斜率或单机高负载游戏表现。8 小时数据只属于内部压力记录。
