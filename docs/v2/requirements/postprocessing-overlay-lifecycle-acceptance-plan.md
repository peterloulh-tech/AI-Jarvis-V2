### 1.1 状态与队列最小观测面

| 观测面 | 必须可关联字段 | 必须可判定的迁移/结果 |
|---|---|---|
| 运行与配置 | `run_id`、`run_generation`、`config_snapshot_hash`、控制状态、`config_locked` | 开始锁定；暂停保持锁定；失败开始或停止清理后解锁；恢复产生新代次 |
| 事件与批次 | `event_id`、`batch_id`、`message_id`、mode、source、`ordinary/highlight`、route | O/V 共用信封；一个主要事件；高光降级后事件等级不改写 |
| 普通发送池 | 批次状态、active/limit、发送窗口、消息数、MP-14/16/17/18 时点 | 首条立即、余下均匀调度；批次进度相互独立；active 不越界 |
| 普通等待队列 | depth/limit/peak、入队顺序、正文是否驻留、MP-14/15、`exit_reason`、`content_age_ms` | 满池入队；满队列淘汰最旧并释放正文；过期不进入显示 |
| 高光路径 | active/limit、独立 route、降级时点与目标 route | 未满立即独立发送；已满整批转普通路径，不拆批、不丢失 highlight 元数据 |
| 校验与重复保护 | 字数、校验结果、完全重复判定摘要、拒绝原因、模型/embedding 调用计数 | 超长整条丢弃；标准化后完全相同文本拦截；不同文本不做语义去重 |
| 组件与资源 | 主程序/模型/采集/Overlay PID 与角色、MP-19～23、显存、剩余 PID、bounded depths | 故障归属、UI 可操作、旧结果失效、停止后本次孤儿为 0 |

缺失导致状态、顺序、容量、代次、路由或清理无法复核的关键字段时，对应条目为 `阻塞`。日志中的弹幕正文遵守既有隐私边界，可用受控样例 ID 与哈希代替；不得为了留证新增原始音画落盘。

### 1.2 可重复输入与符号边界

执行时从配置快照读取普通池上限 `P`、等待队列上限 `Q`、高光并发上限 `H`、发送窗口 `W` 和时效 `T`。分别覆盖 `P-1/P/P+1`、`Q-1/Q/Q+1`、`H-1/H/H+1`；若某下界无效则记 `不适用` 并保留配置证据。`W`、`T` 和调度误差只记录实际值，不由本任务设门槛。

| 输入 ID | 最小内容 | 覆盖 |
|---|---|---|
| POST-IN-01 普通突发 | 可区分事件/批次/消息，覆盖单消息、多消息和多个批次同时发送 | C01～C04 |
| POST-IN-02 高光拥塞 | `H+1` 个可区分高光批次，并能控制普通池/队列状态 | C05、C06 |
| POST-IN-03 校验边界 | 同文、仅空白/标点差异、语义相近但文字不同，以及 60/61 个中文字符样例 | C07～C09 |
| OVERLAY-IN-01 显示样例 | 可识别批次、四个移动方向、横/竖布局边界、三个下层点击目标 | B06～B08 |
| LIFE-IN-01 生命周期 | O/V 各自覆盖空闲、模型忙碌、发送拥塞、在途结果和组件故障 | A06～A08、R01～R08 |
| QUALITY-IN-01 质量回放 | 后续语料任务提供的许可录像、金标、可接受区间和授权引用 | C10 |

## 2. 配置锁与 Overlay P0

| ID | 专项步骤 | 必须留下的证据 | P0 判定增量 |
|---|---|---|---|
| A06 | 点击开始时同时读取所有可编辑项，再尝试修改模式、模型、源、人格、风格和子参数 | 开始前值、只读快照哈希、控件状态、运行实际值 | 开始立即锁定全部配置；本次运行只读值与快照一致，无部分热切换 |
| A07 | 运行后暂停，在模型忙碌和发送拥塞两种状态下重复修改尝试 | 暂停请求、配置锁、允许的控制项、修改拒绝 | 暂停只允许恢复/停止，配置保持锁定且不回滚 |
| A08 | 正常和故障路径分别停止，清理完成前后尝试编辑 | MP-03/04/23、组件/队列/显存、解锁时点 | 清理完成前不提前解锁；完成后配置可编辑，新任务/发送为 0 |
| B06 | 正常初始化一次；停止后注入 Overlay 初始化失败再开始 | Overlay PID/端点、可见性、错误、临时资源、配置锁 | 成功时可见；失败时本次开始失败、无模型/发送/Overlay 残留，返回配置态并解锁 |
| B07 | DISPLAY-001～015 每组分别运行横/竖 Overlay 布局，核对四个方向、固定边/可调边和三个下层点击；另用 TOPO-006 核对物理竖屏 | 每组环境、逻辑/物理矩形、布局、边界、方向、三个点击目标与录屏 | 15 组 × 2 布局均可见、定位正确且点击穿透；任一组合或点击失败即 B07 失败，不跨屏、不做窗口内追踪 |
| B08 | 运行中分别终止 Overlay、断开/禁用目标显示器并释放在途结果 | MP-19～21、控制状态、下游计数、PID/显示拓扑 | 自动暂停；故障后新分析/生成/发送为 0；不可见内容不显示；不自动重启、迁移或恢复 |

Overlay 速度记录必须遵守 [DECISIONS.md](../memory/DECISIONS.md) 的三档与长期比例决定：每条消息的速度档在生成后处理阶段确定一次，模型不参与，运行中不改变。具体持续时间和约 ±8% 扰动仍待 Windows 真机校准，本任务不据此写通过线。

## 3. C01～C10 后处理矩阵

| ID | 专项步骤 | 必须留下的证据 | 判定增量 |
|---|---|---|---|
| C01 | O/V 各注入普通、高光和空结果，沿模型结果、校验、路由、发送、日志、历史/高光时间线和 Overlay 关联同一事件 | 信封/批次字段、来源、等级、批次和各阶段 ID | 两模式共用同一信封和后处理；一个主要事件；空结果不造批次；无分叉协议，P0 |
| C02 | 用 POST-IN-01 覆盖单/多消息及 `P-1/P/P+1` 批次；并行推进两个不同长度批次 | MP-14/16～18、计划/实际发送时点、active/limit、批次各自进度 | 每批第一条立即调度，其余在 `W` 内均匀调度；普通 active 不超过 `P`；批次互不阻塞，P0 |
| C03 | 先占满 `P`，再填至 `Q`，随后加入两个可辨认新批次 | 队列逐次快照、峰值、入队序、淘汰 ID、正文释放与轻量元数据 | 队列不超过 `Q`；满时每次淘汰最旧；被淘汰正文释放且不会显示，P0 |
| C04 | 构造年龄略小于/等于/大于 `T` 的队首，分别释放普通池槽位，并在显示前再次校验 | `observed_at`、入/出队与显示前判定、`content_age_ms`、原因 | 仅有效队首被领取；过期批快速删除且显示数为 0；年龄包含生成与等待，P0 |
| C05 | 普通池保持满载，提交 `H-1/H` 个高光批次 | 高光与普通 active/limit、route、入队/发送时点 | 高光未满时立即走独立流程，不占普通池且不超过 `H`，P0 |
| C06 | 高光 active=`H` 时再提交一个完整高光批次，并分别让普通池空闲、满载和队列满载 | 原事件等级、整批消息、降级时点、普通 route/队列/时效、历史/时间线 | 整批转普通流程并遵守普通容量、淘汰和过期；样式可普通化但 highlight 元数据不改写，P0 |
| C07 | 在同一批次及配置的短跨批窗口内提交同文及仅空白/标点不同样例 | 受控文本哈希、标准化判定摘要、拒绝原因、显示计数 | 标准化后完全相同文本被拦截；原因可追溯，P0 |
| C08 | 跨槽位/批次提交语义相近但文字不同的持续事件样例 | 各文本哈希、批次/发送结果、事件冷却与 embedding 调用计数 | 不同文本全部按普通规则处理；事件冷却、语义去重和 embedding 调用均为 0，P0 |
| C09 | O/V 分别提交恰好 60 和 61 个中文字符的有效结构化文本 | 字数、校验/丢弃原因、后续调用数、显示结果 | 60 字继续后续规则；61 字整条丢弃，不截断、改写或补调用，P0 |
| C10 | 用 QUALITY-IN-01 分模式回放普通/高光/平静场景并关联原始结果、人工评分和时效 | 许可、资产/金标版本与哈希、原始结果哈希、评分、空结果、时效和区间 | 数据完整才表示 P1 已测试；阈值保持待选型校准，不接官方数据、内存、注入或第二模型 |

C02 的“均匀”先按调度计划与相邻间隔一致性判结构，实际计时误差继续作为数据记录；C03～C06 的容量只验证运行配置有界和冻结退出路径，不把某个 `P/Q/H/T` 值升级为产品承诺。

### 4.1 故障与资源清理证据摘要

不创建新模板。每个 A08/B06/B08/R01～R08 运行在既有可靠性登记中至少引用：`reliability_run_id/FAULT ID`、配置与输入哈希、注入时点、故障前后组件 PID/代次、池/队列/槽的 limit/peak/exit reason、MP-03/04/19～23、显存前后、剩余 PID/孤儿、UI/LOG/RES 原始证据和四态结论。容量/时效数据写入既有性能与资源 CSV；Windows 显示结果写入既有兼容 CSV。
