原始录像和音轨只能位于仓库外的受控测试资产区。仓库、应用安装区、运行日志、诊断包和测试结果只保存资产 ID、SHA-256、版本、授权引用和脱敏结论，不保存原始音画。预置测试资产不计为产品运行产生的落盘文件；执行前后仍须证明应用新增的原始图像、视频或音频文件数为 0。任何缺少许可、完整性或脱敏记录的包均不得执行，结果记为 `阻塞`。

## 2. 语料包与许可记录

每个不可变语料包由 `manifest`、`license_record`、`redaction_record`、`timeline` 和 `gold` 五类逻辑记录组成。它们可以由资产管理系统实现，本任务不新建文件模板。

### 2.1 Manifest 最小字段

| 字段组 | 必填字段 | 规则 |
|---|---|---|
| 身份 | `corpus_version`、`package_id`、`asset_id`、`derived_asset_sha256` | 任一媒体或标注变化都生成新版本和哈希 |
| 媒体 | `duration_us`、容器/编码、宽高/FPS、音轨 ID/类型/采样参数 | 视频、麦克风、游戏进程音频、系统混合音频分轨登记 |
| 关联 | `license_record_id`、`redaction_record_id`、`timeline_version`、`gold_version` | 五类记录必须闭环且版本不可混用 |
| 用途 | `allowed_use`、`mode_scope`、`scenario_ids`、`retention_class` | 选型、协议验证、回归、训练等用途分列；默认不含训练授权 |
| 完整性 | 各轨 SHA-256、派生工具/参数、创建/复核人和日期 | 执行时逐项复算；不一致即 `阻塞` |

### 2.2 许可与脱敏

`license_record` 至少记录来源/权利人、取得方式、授权证据引用、允许用途、地域/期限、是否允许派生和人工标注、参与者同意、第三方内容限制、复核人和到期处置。公开可访问不等于获准使用；来源 URL 不能替代许可。授权范围不含训练时，资产和标注不得用于训练或再分发。

`redaction_record` 至少记录原始资产哈希、处理工具/版本、处理区间、玩家/主播姓名、账号、聊天、通知、桌面路径、头像和非必要人声等风险项的删除/遮挡/变声动作、派生哈希及双人复核结论。脱敏不得改变事件顺序、普通/高光语义或音频失效标记；无法兼顾时弃用该片段。仓库内许可索引只保留非敏感引用和结论，敏感合同、同意书及原始身份信息留在受控证据区。

## 3. 场景目录与 O/V 复用

| 场景 ID | 最小内容 | O 使用 | V 使用 | 主要覆盖 |
|---|---|---|---|---|
| SCN-GEN-CALM | 通用平静画面，跨多个系统节奏且无强制事件 | 画面及允许音轨 | 固定帧序列 | 智能沉默、空结果、误报 |
| SCN-GEN-EVENT | 非游戏的普通变化与高变化片段，事件语义可人工复核 | 持续音画 | 1/2/3 路、1/2/3 图派生 | 通用协议、变化与事件分离 |
| SCN-LOL-CALM | 英雄联盟稳定对线/等待等平静片段 | 持续音画 | 固定帧序列 | 平静、空结果、相关性 |
| SCN-LOL-ORDINARY | 可独立描述但非高光的普通事件 | 持续音画 | 普通候选/多图 | `ordinary`、时效、可接受输出 |
| SCN-LOL-HIGHLIGHT | 团战、击杀或目标争夺等经人工确认的高光事件 | 持续音画 | 高变化候选/多图 | `highlight`、降级后元数据 |
| SCN-AUDIO-MATRIX | 画面单独，以及画面加麦克风、游戏进程音频、系统混合音频和获准组合 | 各轨开关分组 | 仅复用视频轨 | 音频组合、轨道关联 |
| SCN-SOURCE-FAIL | 单音轨失效、全部音轨失效、无有效新帧、画面源失效 | 剩余输入/纯画面路径 | 采集失效路径 | 降级、自动暂停、故障证据 |
| SCN-STRUCTURED | 普通、高光、空结果、部分无效和乱序/过期变体 | O-IN-05～07 | V-IN-05～07 | 结构校验、摘要、复位 |
| SCN-LONG-04H/08H | 由上述包按固定计划拼接，不把循环次数当独立质量样本 | 分模式执行 | 分模式执行 | D04、资源、淘汰与恢复 |

同一源录像可派生 O 的连续音画和 V 的固定帧/多图输入，但两者必须引用同一 `asset_id` 和时间轴。音频分组至少覆盖未启用、每种单路、获准多路组合、单路运行中失效和全部运行中失效；未失效轨必须连续。画面变化程度与人工事件等级分别标注，变化分数不得代填 `ordinary/highlight`。源失效只提供可控输入和时间标记，期望动作继续以 O/V、可靠性和生命周期方案为准。

## 4. 单调时间轴格式

所有耗时以语料起点为零的整数微秒表示；执行器把 `asset_t_us` 映射到本机 `captured_at` 等单调时点。UTC 只用于运行关联，不参与耗时。轨道时间戳必须单调非降，事件区间不得超出资产时长。

| 字段 | 含义 |
|---|---|
| `timeline_event_id`、`asset_id`、`timeline_version` | 唯一身份与版本闭环 |
| `asset_t_start_us`、`asset_t_anchor_us`、`asset_t_end_us` | 区间、主要观察点和结束点，满足 start ≤ anchor ≤ end |
| `track_id`、`sequence`、`source_t_us` | 轨道、顺序号及原始 PTS；派生帧/音频块可反查 |
| `kind` | `content_event`、`source_state`、`fault_injection`、`run_control` 或 `replay_marker` |
| `state/action`、`reason`、`payload_ref` | 只放枚举、受控样例 ID 或哈希，不放原始正文/音画 |
| `run_t_us`、`loop_index` | 4/8 小时编排中的运行时点和循环编号；普通短片可为空 |

执行记录必须保留 `scenario_run_id`、配置/构建、模式、资产与轨道哈希、播放倍率、暂停/跳帧/断流、执行器版本，以及 `observed_at`、`captured_at`、`submitted_at`、`result_completed_at`、`validated_at`、`enqueued_at`、`first_displayed_at` 的关联。需要制造失效、过期、淘汰、会话重建、V 全局复位或进程重启时，计划标记和系统实际信号分开记录；未发生的计划动作不能写成已执行。

## 5. 金标与评分规则

### 5.1 事件金标

每个 `gold_event` 至少包含：`gold_event_id`、关联时间轴区间、`scene_class`、`event_label`（`none/ordinary/highlight`）、独立的 `visual_change_band`、必要模态、可接受意图集合、禁止事实/风格集合、`empty_policy`（`must/may/must_not`）、匹配窗口、标注人、复核人、分歧与裁决、版本和哈希。

金标描述“可以表达哪些事件意图及不能声称什么”，不保存唯一标准文案。模型文本命中任一可接受意图、没有命中禁止项且满足冻结结构/字数/风格边界，即可记为语义可接受；措辞不同不能单独判错。事实无法从许可音画确认、侮辱/歧视/引战、胜利承诺或越出第一版来源边界的输出必须单独标记，不得靠总体平均掩盖。

每个事件至少由两名标注者独立标注。`event_label`、时间锚点或可接受意图存在分歧时必须保留原判和裁决；未裁决样本为 `unscorable`，不能进入质量分母。英雄联盟高光由可见/可听事件语义人工确认，不由帧差、音量或官方数据自动决定。

### 5.2 逐结果匹配与汇总

1. 按同一 `scenario_run_id`、`asset_id` 和模式，把有效结果与金标匹配窗口做一对一匹配；重复结果不能重复命中同一金标。
2. 每个金标记录 `matched/missed/unscorable`，每个未匹配结果记录 `spurious/out_of_window`；普通、高光、平静和源失效分组独立保留分母。
3. 事件评分报告 TP/FP/FN 和精确率/召回率原始分子分母；高光评分只在独立事件标签上计算，不使用变化分数替代。
4. 语义评分逐条记录可接受意图命中、禁止项命中、结构有效、相关性和最终人工结论；不把单一文案相似度作为正确答案。
5. 时效使用 `observed_at → first_displayed_at`，按 O/V、普通/高光及降级路径记录 N、min、max、P50、P95、过期/淘汰/失败；P50/P95 复用 nearest-rank。
6. 空结果按 `empty_policy` 判定：`must` 有输出即误报，`must_not` 无输出即漏报，`may` 只记录不强制；显式失败不得伪装为空结果。

C10 只要求原始结果、评分者、匹配、时效、空结果和分母可审计。事件/高光质量、相关性、时效和可接受率的最终门槛全部保持 `null/pending_calibration`，数据完整时使用 `DATA_COMPLETE_PENDING_CALIBRATION`；缺许可、金标、原始结果哈希、关键时点或人工复核时使用 `DATA_INCOMPLETE`/`阻塞`，不得写成质量通过。

## 6. 4/8 小时回放编排

| 窗口 | 编排规则 | 记录与结论边界 |
|---|---|---|
| 4 小时正式 | O/V 分开；固定包、固定配置、正常场景计划；不注入异常。循环须记录 `run_t_us/source_t_us/loop_index` | 可作为 P0 长稳证据；复用资源 CSV 和可靠性 4h 表，记录崩溃、可停止、有界结构、自然发生的过期/淘汰/重建/重启及停止清理 |
| 8 小时内部 | O/V 分开；预先登记场景阶段、源失效和故障注入次数，可重复触顶、恢复与重启 | 只作内部工程证据；记录资源趋势、过期、淘汰、降级、O 会话重建/进程重启、V 全局复位/进程重启和恢复失败，不形成对外承诺 |

编排记录至少引用 `schedule_version`、包/金标哈希、每阶段起止、循环编号、轨道状态、控制/故障计划和证据根路径。循环片段只增加稳定性运行时长，不增加独立质量样本数；C10 质量统计按唯一金标事件和预先声明的重复策略去重。资源、队列、日志、历史、重建/重启、过期、淘汰和停止结果直接填写既有性能/可靠性模板，不建立新 CSV。

## 7. 覆盖与真实缺口

| 验收面 | 规划覆盖 |
|---|---|
| 场景 | 通用、英雄联盟普通/高光/平静、音频组合、源失效 6/6 |
| O/V 输入 | O-IN-01～07 共 7/7；V-IN-01～08 共 8/8；QUALITY-IN-01 1/1 |
| 评分 | 事件、高光、时效、空结果、语义可接受区间 5/5 |
| 治理 | 来源许可、用途、脱敏、完整性、保留/处置 5/5 可审计 |
| 长稳 | 4 小时正式与 8 小时内部 2/2；资源、过期、淘汰、重建/重启均有记录入口 |

真实缺口仍是：尚无已获许可并完成脱敏的实际录像/音轨，未形成正式标注团队、双人复核和裁决数据；候选模型、量化和运行时未选定；C10 的事件/高光质量、相关性、时效和可接受率门槛仍待选型后校准；4/8 小时、Windows/NVIDIA、O 自主触发、V 多图、源失效、资源趋势和恢复数据均未执行。本交付只冻结语料与金标契约，不宣称任何资产、模型能力、质量、性能或稳定性已通过实测。
