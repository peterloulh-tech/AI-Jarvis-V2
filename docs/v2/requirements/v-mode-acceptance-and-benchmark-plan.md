## 2. 回放、金标与注入输入要求

输入资产由后续语料任务制作；本任务只固定可执行 V01～V10 的最小内容与元数据。原始画面遵守许可、脱敏和默认不落盘边界，执行记录只保存资产哈希、时间标记、金标版本与授权引用。

| 输入 ID | 最小内容 | 必须记录 | 覆盖 |
|---|---|---|---|
| V-IN-01 共享并发 | 同一固定录像派生 1/2/3 路可区分时间线，含普通变化和高变化区段 | 各路帧序号/采集时间、服务/进程/权重实例、槽位领取与完成 | V01、V02、V10 |
| V-IN-02 缓冲与最新槽 | 槽位持续忙碌期间快速送入一串可辨认普通帧，随后分次释放槽位 | 环形缓冲容量/峰值/覆盖、普通最新槽写入/领取、未提交帧序号 | V02、V03 |
| V-IN-03 候选保护 | 低分、高分、同分较新、保护期内和过期候选；另有独立人工普通/高光金标 | 变化分数、产生/替换/过期/领取时间及原因、模型事件等级 | V02、V04、V06 |
| V-IN-04 单次多图 | 同一事件的 1/2/3 张连续画面组，画面有方向和边缘标记 | 原始尺寸、缩放/留边、组内采集时间、调用 ID、调用数 | V05、V10 |
| V-IN-05 完整结构化结果 | 普通、高光、空结果及可选客观摘要的可复核片段 | 原始响应哈希、主要事件、等级、风格批次、摘要、校验和额外调用数 | V06、V08 |
| V-IN-06 风格与乱序摘要 | 含重复项的 4+ 风格列表；可使新旧任务乱序完成、失败和过期的连续事件 | 提交顺序、固定风格索引、完成顺序、摘要来源采集时间与更新决定 | V07、V08、V09 |
| V-IN-07 复位与服务故障 | 可控单任务失败/长尾、共享进程退出、暂停/恢复和旧代次结果 | 故障信号、全局复位、代次、全部槽位、旧结果、重启尝试与停止清理 | V09 |
| V-IN-08 V10 基准 | 各硬件组复用同一许可录像，并固定模型、量化、运行时和配置 | 1/2/3 路、可选 1/2/3 图的原始性能/资源记录及主页面提示 | V10 |

金标必须把“画面变化程度”和“事件 ordinary/highlight”分列；两者可以相关但不得互相代填。质量阈值、候选门槛、保护期、摘要有效期、多图间隔和采样率沿用当前校准分组，仅作对照数据，不在本任务冻结。

## 3. V01～V09 P0 专项执行矩阵

以下是在任务 9 对应行上的最小增量。任一冻结规则失败即为该 ID `失败`，不得用平均值、其他并发组或后续成功覆盖。

| ID | 专项步骤 | 必须留下的证据 | P0 判定增量 |
|---|---|---|---|
| V01 | 对 V-IN-01 分别启用 1/2/3 路，在空闲、全忙、任务完成和停止阶段枚举服务、权重与槽位；核对每个输入只被原子领取一次 | 服务/PID/权重标识、槽位状态迁移、任务与输入关联、停止后资源 | 每组始终一个共享服务和一份权重；槽位不绑定来源；重复任务为 0 |
| V02 | 让槽位交替空闲，依次组合“有效候选＋普通新帧”“候选过期＋普通新帧”“仅普通新帧”和“无新输入” | 每次领取前的候选/普通槽快照、原子领取结果、领取原因和任务 ID | 空闲槽立即优先领取有效候选，否则领取最新普通画面；无有效输入不造任务，不按 O 固定节奏 |
| V03 | 占满槽位后连续写入 V-IN-02，释放一个槽，再重复直到所有标记可核对 | 环形缓冲容量/峰值/覆盖、普通最新槽、被提交与被覆盖帧序号 | 缓冲有界；释放后只提交最新未分析普通画面；旧普通画面不形成积压队列 |
| V04 | 顺序写入低分、高分、同分较新和过期候选，并在不同时间释放槽位；对照独立事件金标 | 候选槽深度、每次替换/保留/过期/领取原因、变化分数与模型等级分列 | 候选最多 1 个，按分数和较新时间保护并优先领取；过期候选不提交；变化分数不直通高光 |
| V05 | 对 V-IN-04 的 1/2/3 图各提交一次，并在不同并发组复核调用边界 | 输入组预览/哈希、原始尺寸、缩放/留边、调用 ID、图数与调用计数 | 每个画面组只产生一次模型调用；保持宽高比并留边；无超分、OCR 或第二次补调用 |
| V06 | 分别回放普通、高光和空结果片段，检查一次推理的完整结构化响应与后续调用 | 原始响应哈希、主要事件数、等级、风格批次、可选摘要、调用链 | 同次推理完成一个主要事件、`ordinary/highlight`、一个风格批次和可选摘要；无分类/摘要补调用；高光由模型事件结论产生 |
| V07 | 按提交顺序创建并发任务，再故意乱序完成、失败和过期；停止后新建会话重复首轮 | 提交/完成顺序、任务固定风格、轮询前后索引、人格/语言/安全快照 | 风格在提交时按顺序固定并推进，完成乱序、失败或过期均不回滚；新会话从首项开始 |
| V08 | 开关前序上下文；制造旧任务后完成、新任务先完成、空结果和过期结果 | 每个任务附带摘要、摘要来源 `captured_at`、更新前后值、额外调用数 | 每任务最多附最近 1 条有效客观摘要；只允许更新采集时间更晚的有效摘要；空/过期/旧摘要不覆盖；无历史弹幕或额外调用 |
| V09 | 先释放一个过期结果；再在任务在途时暂停/恢复或注入共享服务退出，提升代次后释放旧结果及当前代次有效结果 | 过期判定、复位前后代次、所有槽位/缓冲/摘要状态、丢弃原因、UI/停止能力 | 过期和旧代次结果均不显示、不更新摘要；全局复位统一失效旧任务并使用新代次；当前代次有效结果仍按时效进入后续流程 |

## 4. 并发、乱序与复位判定表

| 场景 | 必须发生 | 禁止结果 | 结论依据 |
|---|---|---|---|
| 多槽位同时可领取 | 对候选/普通输入执行原子领取，每个输入绑定唯一 `task_id` | 重复提交、按来源复制服务/权重 | 领取日志＋服务/权重枚举 |
| 完成顺序不同于提交顺序 | 结果按各自任务校验；风格使用提交时固定值 | 按完成顺序重新分配风格、失败回滚风格 | 提交/完成序列＋风格索引 |
| 新摘要先完成、旧摘要后完成 | 以摘要来源 `captured_at` 比较，只保留较新有效摘要 | 旧完成结果覆盖新摘要 | 摘要更新前后日志 |
| 任务失败、空结果或过期 | 释放槽位并记录原因；不产生无效摘要更新 | 立即补调用、回滚风格、过期内容进入显示 | 任务状态迁移＋调用链 |
| 暂停/恢复或共享服务故障 | 按既有故障矩阵全局复位、提升 `run_generation`，旧在途结果失效 | 局部槽位沿用旧代次、第二份权重、无限重启 | FAULT-005～007/012～014 记录 |
| 旧代次结果晚到 | 在校验或更早边界丢弃，摘要/队列/Overlay 均不接收 | 旧结果显示或改变当前摘要 | 代次校验＋下游计数 |
| 当前代次有效结果乱序到达 | 在未过期且结构有效时按既有下游规则处理 | 为保持顺序新增长期结果队列或事件去重 | 校验、时效与下游关联日志 |

V 推理硬超时和连续重启保护阈值分别保持 `CAL-022`、`CAL-023` 待实测/评审；本表只判定隔离、有界、代次和可停止结果，不填写秒数或次数。

## 5. V10 P1 基准记录与完整性

V10 不以“方案已写”判通过。Windows 11 64 位、NVIDIA 环境按 V 8GB 目标组和 12GB+ 推荐组分开执行 V-IN-08；硬件表述只作产品边界与分组，不自动成为性能通过线。每个 `vram_class × concurrency × image_count` 组合必须新建 `sample_group`，复用任务 3 的性能/资源 CSV 和汇总模板。

### 5.1 执行顺序

1. 锁定应用、模型、量化、运行时、硬件/驱动、配置、回放哈希和样本规则，记录加载前资源。
2. 分别对 1/2/3 路运行同一回放，证明始终一个服务/一份权重；按适用组合再分 1/2/3 图，图数组不得混算。
3. 记录加载、稳态、忙碌、故障/过期和停止阶段；用 MP-05/06/09/10/12/22/23 关联 MET-T05/T06、R01/R02/R06、C08、S08/S09。
4. 每组报告 N 总计及成功/失败/超时/取消/过期分母、min/max/P50/P95、吞吐、显存/GPU 时序和共享权重实例数；P50/P95 使用既有 nearest-rank 规则。
5. 保留主页面性能提示、原始记录、日志和限制；停止后核对资源与孤儿。只使用既有结果标记，不自动降级配置。

### 5.2 V10 报告模板

| 证据组 | 必填字段/证据 | 完整性判定 |
|---|---|---|
| 候选与环境 | 应用提交/构建、model/version、quantization、runtime/version、Windows/驱动、GPU/显存、CPU/RAM、电源策略 | 任一关键身份缺失则 `DATA_INCOMPLETE` |
| 分组 | `scenario_run_id`、资产/金标哈希、`vram_class`、concurrency、image_count、配置/预热/纳入规则 | 不同控制变量不得合并 |
| 共享实例 | 服务/PID、权重标识和实例数、槽位数、任务关联 | 共享服务/一份权重失败按冻结规则判 `FAIL_FROZEN` |
| 延迟与吞吐 | N 及结果分母、MET-T05/T06 的 min/max/P50/P95、吞吐、忙碌比例 | 数据齐全仅表示 P1 已测试，不形成门槛 |
| 资源与停止 | 显存/GPU/内存/句柄初值、P50/P95/max、末值、停止后基线、剩余 PID/孤儿 | 缺原始时序或进程归属则 `DATA_INCOMPLETE` |
| 调度与恢复 | 候选/普通领取、覆盖/过期、摘要乱序、复位/重启和失败计数 | 阈值保持待实测；异常逐次保留 |
| UI 与结论 | 主页面性能提示、结果标记、限制、证据路径、待评审项 | 不自动降级，不把实测值写成对外承诺 |
