# AI Jarvis V2 Windows 真机与硬件验收矩阵

> 任务：AIJARVISV2-14
>
> 唯一功能范围、正式质量约束和候选验收版本沿用 [baseline-manifest.md](baseline-manifest.md)，不在本任务改写。

本文件把既有 Windows、性能、可靠性、离线和 O/V 验收资产编排到代表性物理机；不复制场景步骤，不承诺覆盖所有硬件，也不把规划写成真机通过。每次执行只允许结论 `通过`、`失败`、`阻塞`、`不适用`。

## 1. 共用前置与复用入口

正式组合均须为 Windows 11 64 位、NVIDIA 独显、简体中文、本地物理机交互会话。完整离线安装包先在联网准备机核对清单与哈希，复制到目标机后按 [offline-install-update-validation-plan.md](offline-install-update-validation-plan.md) 的 `INSTALL-TEST-002` 切断主机外部网络；O/V 核心闭环分别执行 `OFFLINE-TEST-001/002`。本机 IPC 单独记录，不计外连。

| 证据类别 | 唯一复用入口 | 本任务用途 |
|---|---|---|
| Windows 环境、显示、采集、设备 | [windows-validation-record-templates.md](windows-validation-record-templates.md) 及既有 CSV | 机器、驱动、显示、源、设备和兼容结果 |
| 性能与负载 | [performance-record-templates.md](performance-record-templates.md) 及既有两个 CSV | 模型/运行时、GPU/显存/CPU/内存、P50/P95 和资源趋势 |
| 锁屏、睡眠、休眠与停止 | [reliability-test-and-record-templates.md](reliability-test-and-record-templates.md) 及事件 CSV | `FAULT-014` 触发、停止清理、唤醒后状态 |
| 安装、断网与包版本 | [offline-install-update-validation-plan.md](offline-install-update-validation-plan.md) 及既有离线记录 CSV | 包清单、哈希、网络阻断和 O/V 离线闭环 |
| O/V 专项输入与判定 | [o-mode-acceptance-and-benchmark-plan.md](o-mode-acceptance-and-benchmark-plan.md)、[v-mode-acceptance-and-benchmark-plan.md](v-mode-acceptance-and-benchmark-plan.md) | O10、V10 的模型、并发、图数及结果边界 |

任一应用提交、构建、程序包、模型、量化、运行时、驱动、硬件、显示、输入、游戏版本或网络状态变化都必须建立新的 `sample_group`，不得合并统计。

## 2. 代表性真机组合

三种显存档可由三台物理机承担；同一台机器允许在清空前一运行并建立新 `sample_group` 后承担多个运行档。标称和系统可见显存都须记录。8GB 目标档与 16GB 模型独占档需要各自边界机器；V 推荐档按冻结表述接受 12GB 及以上并记录实际容量。更高显存的 O 机器只能形成补充数据，不能替代 16GB 边界证据。

| 运行档 | NVIDIA 显存与负载 | 模式/场景 | 必做内容 | 可声明边界 |
|---|---|---|---|---|
| `HW-V8` | 8GB；记录全部竞争 GPU 进程 | V 目标档；固定回放 | V10 的 1/2/3 路及 1/2/3 图分组；`DISPLAY-001～005`；`TOPO-001/003/004` | 只说明 8GB 目标档本次数据，不宣称模型能力或性能门槛 |
| `HW-V12` | 12GB 及以上；记录实际容量 | V 推荐档；与 `HW-V8` 相同模型/量化/运行时 | V10 的 1/2/3 路及 1/2/3 图分组；`DISPLAY-006～010`；`TOPO-005` | 只说明推荐档本次数据，不以推荐字样判性能通过 |
| `HW-O16-X` | 16GB 主要供模型使用；关闭游戏及无关 GPU 负载并留证 | O 模型独占；固定持续音画 | O10；低/标准/高和 225/350/500 字组；`DISPLAY-011～015`；`TOPO-002/006` | 只形成 16GB 模型独占能力、资源与稳定性数据 |
| `HW-LOL-V` | 复用 `HW-V8`，实际游戏和 AI Jarvis 负载分列 | 英雄联盟与 V 在同一台机器；1 路 | 窗口化、无边框、全屏；普通/高光/平静场景；开始、运行、停止 | 只适用于该机器、驱动、游戏版本和画质，不外推其他配置 |
| `HW-LOL-O` | 复用 `HW-O16-X`，从独占档另建运行 | 英雄联盟与 O 在同一台机器；O/V 不同时运行 | 三种呈现模式及相同场景；记录游戏与模型竞争负载、降级、停止 | 即使通过也不是 O 单机高负载游戏承诺，且不能替代 `HW-O16-X` |

`HW-LOL-*` 的“一台机器”只表示游戏与 AI Jarvis 同机，不表示断网。如果英雄联盟启动或维持场景需要外部网络，该运行必须记录网络状态并与离线组分开；应用级防火墙或抓包可作补充证据，但不得替代主机断网的 `OFFLINE-TEST-001/002`。三角洲行动不进入第一版必测表，结果一律不得从英雄联盟外推。

## 3. 显示、采集与输入组合

### 3.1 显示与游戏呈现

- `DISPLAY-001～015` 按第 2 节分工全部执行，覆盖 1080P/2K/4K 与 100/125/150/175/200%；每格保留左上、中心、右下可见性与点击穿透证据。
- `TOPO-001～006` 全部执行；多显示器每次只选择一个采集源和一个 Overlay 目标，不允许同时采集多屏或跨屏弹幕。
- `CAPTURE-001～005/012` 使用可控测试画面执行；`CAPTURE-006～011` 先用可控程序执行，再在两个 `HW-LOL-*` 档分别复核窗口化、无边框、全屏及模式切换。
- 横向和竖向 Overlay、透明、置顶、点击穿透继续执行 `OVERLAY-001～008`；明确失效时引用既有故障动作，不自动换源、换屏或换模式后记通过。
- 目标显示器断开/禁用及运行中分辨率/缩放变化执行 `SYSTEM-001～004`；触发后的暂停、清理与恢复动作仍引用任务 4。

### 3.2 O 音频选择与降级

以下五组均复用任务 13 的 `SCN-AUDIO-MATRIX`，记录实际端点/进程 ID、格式、轨道哈希、选中集合和 MP-08 时间轴。系统混合音频必须作为独立来源记录，不能用游戏进程音频代替。

| 组合 ID | 已选择输入 | 主要判定 |
|---|---|---|
| `AUDIO-01` | 仅画面 | 无音频输入；纯画面路径可观察 |
| `AUDIO-02` | 画面 + 麦克风 | 只有选定麦克风进入输入 |
| `AUDIO-03` | 画面 + 英雄联盟进程音频 | 只有选定进程音频进入输入 |
| `AUDIO-04` | 画面 + 系统混合音频 | 系统混合来源可区分、可追溯 |
| `AUDIO-05` | 画面 + 麦克风 + 进程音频 + 系统混合 | 三路身份与时间轴可区分，不产生未选择输入 |

`AUDIO-02/03/05` 分别执行 `DEVICE-001～003`；再在 `AUDIO-05` 上逐路初始化失败、运行中失效并最终全部失效，覆盖 `B04/B05` 与 `DEVICE-004～009`。剩余输入、纯画面降级及禁止自动切换规则仍以既有矩阵为准。V 不启用音频，不得因这组测试扩展 V 输入。

## 4. 系统状态与综合运行

| 组合 | 模式 | 操作 | 必须观察 |
|---|---|---|---|
| `POWER-O-LOCK/SLEEP/HIBERNATE` | O | 分别触发锁屏、睡眠、休眠并唤醒 | `SYSTEM-005～008`、`FAULT-014`；模型/采集/Overlay/显存/子进程清理，唤醒后保持停止且不自动恢复 |
| `POWER-V-LOCK/SLEEP/HIBERNATE` | V | 同上，含 1～3 路中至少一个在途任务 | 全局状态、旧代次结果、共享权重和停止清理可追溯 |
| `LOL-V-COMBINED` | V | 三种呈现模式各运行普通/高光/平静场景后停止 | 游戏与 AI Jarvis 的 CPU/GPU/显存/内存分列；采集、Overlay、结果和停止证据完整 |
| `LOL-O-COMBINED` | O | 同上，含 `AUDIO-02～05` 中实际可用组合 | 持续音画、结构化输出、竞争负载、失败/降级及停止结果完整；性能门槛仍待实测 |

综合运行不允许同时启动 O 和 V，也不增加官方数据、进程内存读取、注入、键鼠模拟或第二模型。英雄联盟普通/高光/平静的事件评分仍引用任务 13 金标；真机矩阵不另建质量阈值。

## 6. 通过与限制声明

- `通过`：只表示该精确 `hardware_profile_id + sample_group + case ID` 的冻结结果或数据完整性满足；P1 性能数据完整不等于性能门槛通过。
- `失败`：冻结可观察结果不满足、出现范围违规或任一 P0 失败；其他机器成功不得覆盖。
- `阻塞`：必测机器/设备/包/模型/游戏场景不可用，关键版本、负载、步骤或证据缺失，或待评审冲突使结论无法形成。缺少必测硬件不得标 `不适用`。
- `不适用`：只用于 Windows 10、非 NVIDIA、虚拟机/云桌面/远程桌面等非正式支持或不承诺探索环境，以及冻结明确排除项；探索成功不得升级支持范围。

每条发布或评审声明必须同时列出精确硬件/驱动/系统/构建/模型/配置、已执行 case、四态结果、证据引用、未覆盖组合和待校准项。禁止使用“8GB/12GB/16GB 均支持全部模型”“O 可与高负载游戏流畅同机运行”“所有 NVIDIA/显示器/音频设备兼容”等外推表述。

| 验收面 | 规划覆盖 |
|---|---|
| 显存与综合运行 | V 8GB、V 12GB、O 16GB 独占、英雄联盟 V/O 同机共 5/5 运行档 |
| 显示与采集 | DISPLAY 15/15、TOPO 6/6、CAPTURE 12/12、OVERLAY 8/8 |
| 音频 | 选择组合 5/5；既有 DEVICE 9/9 与 B04/B05 降级入口均映射 |
| 系统状态 | SYSTEM 8/8；O/V 的锁屏、睡眠、休眠 6/6 模式触发 |
| 断网核心闭环 | O/V 2/2，均引用完整离线包和主机断网步骤 |
| 结论 | 通过/失败/阻塞/不适用 4/4 及限制声明字段 |

真实缺口仍是：没有 8GB、12GB、16GB Windows 11/NVIDIA 物理机、显示器/音频设备、完整离线包和驱动清单的执行证据；候选模型、量化和运行时尚未冻结；15 个显示组合、混合 DPI、多显示器、系统混合音频、三种游戏呈现模式、锁屏/睡眠/休眠、O/V 断网闭环及英雄联盟同机负载均未实测；英雄联盟场景与主机完全断网的可兼容执行方式尚未确认。所有延迟、吞吐、资源峰值/斜率和综合游戏表现继续待实测/评审，本交付只完成矩阵、记录入口和声明规则。
